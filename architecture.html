Core data model

DESIGNUser → ProfileAccount identity connects to country, languages, occupation and learning level.
DESIGNProfile → Learning PathOccupation + country + language determine the learner's training path.
DESIGNLearning Path → EvidenceLessons, practical practice, simulations and assessments create evidence.
DESIGNEvidence → Skill PassportOnly supported, observable learning evidence should appear in the passport.

Production security gates

REQUIREDNo credentials in HTMLBrowser files must never contain passwords, database secrets or private keys.
REQUIREDServer-side authorizationAdmin permissions and protected records must be enforced on the server.
NEXTSecure session systemHttpOnly/Secure/SameSite cookies or another properly designed session mechanism.
NEXTDatabase backupsRecovery, retention and deletion procedures must be defined before production.

Implementation order

  1. Backend foundation — lightweight Python/FastAPI service with environment-based configuration.
  2. Database schema — users, profiles, occupations, content, progress, assessments, evidence and governance.
  3. Authentication — secure password hashing, sessions, verification and reset flows.
  4. API boundaries — validate every request and authorize every protected operation.
  5. Connect learner modules — replace prototype/local storage with server persistence.
  6. Admin governance — content, compliance, audit and publishing controls.
  7. Security test — authorization, input validation, session security, dependency and upload checks before production.
Architecture rule: WHYNZO's current HTML files are front-end prototypes. Do not collect real passwords, sensitive learner data, camera recordings or production assessment evidence until the secure backend, storage, access controls and privacy/retention rules are implemented.
